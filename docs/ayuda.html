1. Instalación

Android

  1. Escanea el código QR de la página de descarga o pulsa "Android (APK)".
  2. Abre el fichero descargado. Si Android lo pide, permite "instalar aplicaciones de origen desconocido".
  3. Abre la app WhatsApp seguro.

Linux

tar xzf whatsapp-seguro-linux.tar.gz
cd bundle
./whatsapp_seguro

Para enviar imágenes en Linux hace falta zenity (sudo apt install zenity).

2. Uso

  1. Entrar: escribe tu nombre y la dirección del servidor (por ejemplo ws://IP_PROXMOX:8080) y pulsa Entrar. La primera vez se generan tus claves automáticamente.
  2. Contactos: a la izquierda aparecen los usuarios. El círculo verde indica que está conectado. Debajo del nombre se ve el último mensaje o "escribiendo..."; el número verde son los mensajes sin leer.
  3. Enviar: pulsa un contacto, escribe y pulsa ➤ o Intro. Con 📎 eliges una imagen (máx. 5 MB).
  4. Estado de los mensajes:
    IconoSignificado
    ✓ grisEnviado al servidor
    ✓✓ grisRecibido por el otro usuario, pero sin leer
    ✓✓ azulLeído (el otro ha abierto el chat)
  5. Historial: las conversaciones se guardan en tu dispositivo y siguen ahí al volver a abrir la app con el mismo nombre.

En Linux (pantalla ancha) la lista y el chat se ven a la vez, como WhatsApp Web. En Android el chat se abre en otra pantalla.

3. Seguridad: cifrado de extremo a extremo

Cada usuario tiene un par de claves X25519:

  • Clave privada: se queda siempre en tu dispositivo. Nunca se envía.
  • Clave pública: se envía al servidor, que la reparte a los demás usuarios.
 Ana                          Servidor                         Pepe
 secreto = X25519(privada Ana, pública Pepe)
 cifrado = AES-GCM(secreto, "Hola")
   ── {to: pepe, nonce, cipher, mac} ──►  (no puede leerlo)
                                      ── {from: ana, ...} ──►
                         secreto = X25519(privada Pepe, pública Ana)
                         "Hola"  = AES-GCM descifrar(secreto, cipher)

Los dos obtienen el mismo secreto sin enviarlo nunca (intercambio Diffie-Hellman). El servidor solo conoce las claves públicas, por eso no puede descifrar nada. AES-GCM además añade un código mac: si alguien modifica el mensaje por el camino, el descifrado falla.

4. Servidor

Servidor Node.js con WebSockets (librería ws) desplegado en el Proxmox del instituto como servicio systemd. Solo hace tres cosas: guardar la clave pública de cada usuario, reenviar mensajes al destinatario y guardar en memoria los mensajes de usuarios desconectados hasta que se conectan.

5. Scripts de validación

Comprueban automáticamente que el servidor del Proxmox funciona. Necesitan Node.js 18 o superior.

git clone https://github.com/USUARIO/m07-publicacion
cd m07-publicacion/tests
./run-tests.sh ws://IP_PROXMOX:8080

Cada prueba crea usuarios de prueba que se conectan al servidor:

PruebaQué comprueba
1El servidor acepta conexiones WebSocket
2Tras el login llega la lista de usuarios con la clave pública y online = true
3Un mensaje cifrado llega al destinatario sin modificar (nonce, cipher y mac idénticos)
4No se puede falsificar el remitente: el servidor pone el from real
5Se reenvía el aviso "escribiendo"
6Se reenvían las confirmaciones de recibido y leído
7Un mensaje a un usuario desconectado le llega cuando se conecta
8Al desconectarse un usuario, los demás lo ven como offline

Al final se muestra un resumen: # pass 8 y # fail 0 indica que todo funciona.
